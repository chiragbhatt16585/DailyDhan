## 1. Create Supabase Project

### Step 1.1: Sign Up / Sign In
1. Go to [https://supabase.com](https://supabase.com)
2. Sign up or sign in to your account

### Step 1.2: Create New Project
1. Click **"New Project"**
2. Fill in:
   - **Name**: `DailyDhan` (or any name you prefer)
   - **Database Password**: Choose a strong password (save it somewhere safe!)
   - **Region**: Choose closest to your users
3. Click **"Create new project"**
4. Wait 2-3 minutes for the project to be ready

### Step 1.3: Get Your API Keys
1. Go to **Settings** → **API** (left sidebar)
2. You'll see:
   - **Project URL**: `https://xxxxx.supabase.co`
   - **anon public key**: A long string starting with `eyJ...`
3. **Copy both values** - you'll need them in step 4

## 2. Set Up Database Tables

### Step 2.1: Open SQL Editor
1. In Supabase dashboard, click **SQL Editor** (left sidebar)
2. Click **"New query"**

### Step 2.2: Run SQL Scripts

Copy and paste each SQL block below into the SQL Editor and click **"Run"**:

#### 2.2.1: Create Wallets Table
```sql
create table if not exists public.wallets (
  id           bigint generated by default as identity primary key,
  user_id      uuid not null references auth.users(id) on delete cascade,
  name         text not null,
  type         text default 'cash',
  bank_name    text,
  last_4_digits text,
  balance      numeric default 0
);

alter table public.wallets enable row level security;

create policy "Wallets are visible only to owner"
  on public.wallets
  for select using (auth.uid() = user_id);

create policy "Wallets insert only for self"
  on public.wallets
  for insert with check (auth.uid() = user_id);

create policy "Wallets update only by owner"
  on public.wallets
  for update using (auth.uid() = user_id);

create policy "Wallets delete only by owner"
  on public.wallets
  for delete using (auth.uid() = user_id);
```

#### 2.2.2: Create Categories Table
```sql
create table if not exists public.categories (
  id      bigint generated by default as identity primary key,
  user_id uuid not null references auth.users(id) on delete cascade,
  name    text not null,
  type    text not null,
  icon    text,
  color   text
);

alter table public.categories enable row level security;

create policy "Categories visible only to owner"
  on public.categories
  for select using (auth.uid() = user_id);

create policy "Categories insert only for self"
  on public.categories
  for insert with check (auth.uid() = user_id);

create policy "Categories update only by owner"
  on public.categories
  for update using (auth.uid() = user_id);

create policy "Categories delete only by owner"
  on public.categories
  for delete using (auth.uid() = user_id);

create unique index if not exists idx_categories_user_name_type
  on public.categories(user_id, name, type);
```

#### 2.2.3: Create Transactions Table

#### 2.2.4: Create Budgets Table
```sql
create table if not exists public.budgets (
  id          bigint generated by default as identity primary key,
  user_id     uuid not null references auth.users(id) on delete cascade,
  category_id bigint not null references public.categories(id),
  amount      numeric not null,
  period      text not null,
  year        integer,
  month       integer,
  created_at  timestamptz default now()
);

alter table public.budgets enable row level security;

create policy "Budgets visible only to owner"
```

#### 2.2.5: Create Recurring Transactions Table
```sql
create table if not exists public.recurring_transactions (
  id               bigint generated by default as identity primary key,

create policy "Recurring visible only to owner"
```

## 3. Configure Google OAuth

### Step 3.1: Create Google OAuth Credentials

1. Go to [Google Cloud Console](https://console.cloud.google.com/)
2. Create a new project (or select existing)
3. Go to **APIs & Services** → **Credentials**
4. Click **"Create Credentials"** → **"OAuth client ID"**
5. If prompted, configure OAuth consent screen:
   - User Type: **External**
   - App name: **DailyDhan**
   - User support email: Your email
   - Developer contact: Your email
   - Click **"Save and Continue"** through the steps
6. Create OAuth client:
   - Application type: **Web application**
   - Name: **DailyDhan Web Client**
   - Authorized redirect URIs: Add:
     - `https://YOUR_PROJECT_ID.supabase.co/auth/v1/callback`
     - (Replace `YOUR_PROJECT_ID` with your actual Supabase project ID)
   - Click **"Create"**
7. **Copy the Client ID and Client Secret** - you'll need them next

### Step 3.2: Add Google Provider in Supabase

1. In Supabase dashboard, go to **Authentication** → **Providers**
2. Find **Google** and click to expand
3. Enable Google provider
4. Paste your **Client ID** and **Client Secret** from Step 3.1
5. Click **"Save"**

### Step 3.3: Add Redirect URL

1. Still in **Authentication** → **URL Configuration**
2. Under **Redirect URLs**, add:
   - `dailydhan://auth/callback` (for mobile app)
   - `https://YOUR_PROJECT_ID.supabase.co/auth/v1/callback` (should already be there)
3. Click **"Save"**

## 5. Configure Deep Links (Mobile)

### 5.1: Android Configuration

1. Open `android/app/src/main/AndroidManifest.xml`
2. Find the `<activity>` tag for your main activity (usually `MainActivity`)
3. Add this inside the `<activity>` tag:

```xml
<intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="dailydhan" android:host="auth" />
</intent-filter>
```

**Full example:**
```xml
<activity
    android:name=".MainActivity"
    android:label="@string/app_name"
    android:configChanges="keyboard|keyboardHidden|orientation|screenLayout|screenSize|smallestScreenSize|uiMode"
    android:launchMode="singleTask"
    android:windowSoftInputMode="adjustResize"
    android:exported="true">
    <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent-filter>
    <!-- Add this for deep linking -->
    <intent-filter>
        <action android:name="android.intent.action.VIEW" />
        <category android:name="android.intent.category.DEFAULT" />
        <category android:name="android.intent.category.BROWSABLE" />
        <data android:scheme="dailydhan" android:host="auth" />
    </intent-filter>
</activity>
```

### 5.2: iOS Configuration

1. Open `ios/DailyDhanFull/Info.plist`
2. Add this inside the `<dict>` tag (before `</dict>`):

```xml
<key>CFBundleURLTypes</key>
<array>
    <dict>
        <key>CFBundleTypeRole</key>
        <string>Editor</string>
        <key>CFBundleURLSchemes</key>
        <array>
            <string>dailydhan</string>
        </array>
    </dict>
</array>
```

### 5.3: Install Deep Link Handler (Optional but Recommended)

For better deep link handling, you can install:

```bash
npm install react-native-linking --legacy-peer-deps
```

Then update your `RegistrationScreen.js` to handle the callback URL properly.

## 6. How Migration Works

### Overview

When a user logs in with Google for the first time:

1. **Registration Screen** appears
2. User taps **"Continue with Google"**
3. Browser opens → User signs in with Google
4. Browser redirects back to app via deep link
5. App detects login → Checks for local data
6. If local data exists → Shows migration prompt
7. User chooses to migrate → All local data is uploaded to Supabase
8. User is taken to main app

### What Gets Migrated

The migration script (`src/database/migrateToSupabase.js`) exports:

- ✅ **Categories** (with icons and colors)
- ✅ **Wallets** (with balances and details)
- ✅ **Transactions** (all historical data)
- ✅ **Budgets** (monthly and yearly)
- ✅ **Recurring Transactions** (with schedules)

### Migration Process

1. **Reads** all data from local SQLite database
2. **Maps** old local IDs to new Supabase IDs (important for foreign keys)
3. **Inserts** data in correct order:
   - Categories first (no dependencies)
   - Wallets second (no dependencies)
   - Transactions third (needs categories & wallets)
   - Budgets fourth (needs categories)
   - Recurring transactions last (needs categories & wallets)
4. **Tracks** migration status to avoid duplicate migrations

### Migration Status

- Migration status is stored in `AsyncStorage` with key: `@dailydhan_migration_complete_{userId}`
- Once migrated, the app won't prompt again
- If migration fails, user can retry later

## 🧪 Testing

### Test the Setup

1. **Build and run** your app
2. You should see the **Registration screen** first
3. Tap **"Continue with Google"**
4. Sign in with Google
5. If you have local data, you'll see the migration prompt
6. After migration, check Supabase **Table Editor** to see your data

### Troubleshooting

**Problem: "Invalid API key"**
- ✅ Check `src/config/supabase.js` has correct URL and key
- ✅ Make sure you copied the **anon public** key (not service role key)

**Problem: "OAuth error"**
- ✅ Check Google OAuth credentials are correct in Supabase
- ✅ Verify redirect URL in Google Cloud Console matches Supabase callback URL

**Problem: "Deep link not working"**
- ✅ Check AndroidManifest.xml and Info.plist are configured correctly
- ✅ Rebuild the app (not just reload)
- ✅ Test on a real device (simulators sometimes have issues)

**Problem: "Migration fails"**
- ✅ Check Supabase tables exist and have correct schema
- ✅ Check RLS policies are set up correctly
- ✅ Check browser console for detailed error messages
